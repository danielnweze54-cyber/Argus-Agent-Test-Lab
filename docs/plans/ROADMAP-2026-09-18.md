# Argus × Secretariat: x402 — решения на 2026-09-18

**Статус:** DRAFT, не коммит. Дайджест для восстановления контекста.
**Контекст:** сессия разбора x402-интеграции. Эксперимент Qwen (локальное
подключение проектов) — отдельная задача, не этот ROADMAP.

---

## Принято

1. **Secretariat → x402 Resource Server** (входящий edge).
   Не buyer. Не facilitator.

2. **Argus → минимальный x402 client** (4 шага как composable-примитивы,
   не автоматический цикл). Scope-limiter: ровно 4 шага, никакого SDK.

3. **Порядок работы:** последовательный.
   Secretariat edge → референсный клиент (curl + скрипт-подписант,
   **не Argus**) → зелёный ручной e2e → Argus против проверенного контракта.
   Параллельный порядок отвергнут (gap известен статически, но wire-формат —
   нет; угадывать его двумя сторонами = interop-фейл без возможности
   установить виновника).

4. **Scope-limiter Argus:** 4 шага + wire-codec (чистые функции) +
   signer (отдельно от сборщика payload — чтобы сценарий мог исказить
   payload до подписи или подпись после) + mock x402 seller как fixture
   для самотестов Argus.

5. **Scope-limiter Secretariat:** 402 + `PAYMENT-REQUIRED` /
   `PAYMENT-SIGNATURE` / `PAYMENT-RESPONSE` + base64 + CAIP-2.
   Facilitator: V0 — без него (прямой on-chain `transferWithAuthorization`
   через viem), V1 — опциональный путь. Не быть facilitator'ом.

6. **Окно 200:** ждать reconciliation в bounded-окне; за окном —
   `PAYMENT_UNKNOWN` (не 500, не ложный 200). Режим «доверять facilitator'у
   сразу» — второй режим позже.

7. **Nonce idempotency:** `authorization.nonce` = idempotency key.
   Повтор того же payload возвращает текущее состояние операции,
   не ошибку. Обязательное требование.

8. **DELIVERY_UNKNOWN на сервере** — открытый вопрос.
   V0: 500 + статус операции параллельно (в отдельном канале).
   Позже — модель «ресурс = принятие заявки, исход execution отдельно».

## Роли: две оси соединения Argus ↔ Secretariat

Эксперимент Qwen 2026-09-18 показал, что проекты соединяются двумя
способами. Это **не противоречие** — это две разные оси.

**Ось 1 — x402 wire (основная задача):**
Argus — buyer, Secretariat — seller.
Реализуется по этому ROADMAP.

**Ось 2 — PaymentSigner (отдельный трек):**
Secretariat — orchestrator, Argus — внешний signer.
Эксперимент показал: интерфейсы совместимы (`PaymentSigner` ↔ `PaymentAdapter`).
Не конфликтует с осью 1, но и не заменяет её.

### Матрица ролей

| Сущность | buyer | seller | orchestrator | signer |
|---|---|---|---|---|
| **Argus** | ✅ | ✅ | ❌ | ✅ |
| **Secretariat** | ❌ (сам не платит) | ✅ (x402 edge) | ✅ (его природа) | ❌ (нет ключей) |

**Ключевое ограничение:** Secretariat **сам не платит**. Подпись — всегда
внешняя (через `PaymentSigner`). Ось 2 не делает Secretariat buyer'ом.

**Что это значит для x402:** ось 1 — основная задача. Ось 2 — отдельная
возможность. `ArgusPaymentAdapter` в Secretariat **не является ошибкой** —
он использует существующий интерфейс. Но он **не** является путём к
x402-интеграции.

## Что НЕ делать

- **Не** превращать Argus в полноценный x402 SDK.
- **Не** добавлять x402 в Secretariat «на всякий случай».
- **Не** писать `/v1/argus/*` в Secretariat (special-case).
- **Не** удалять `AgentTargetPort`, Model V0, Target Opaque.
- **Не** трогать: state machine Secretariat, reconciliation,
  durable intent, nonce registry, post-settlement execution, evidence.
- **Не** считать `ArgusPaymentAdapter` в Secretariat ошибкой — он
  корректен, но это ось 2, не ось 1.
- **Не** считать `zeus-integration.test.ts` в Argus ошибкой — это
  артефакт эксперимента, не часть x402-интеграции.

## История отвергнутого

- **`/v1/argus/ping`** — special-case, нарушает Target Opaque.
- **`/v1/exchange`** — facade, не нужен, если Secretariat x402-совместим.
- **`SecretariatTargetAdapter` в Argus** — legacy, удалено в 7.2a/b.
- **Вариант A** (Argus → native Secretariat API) — native API не знает
  реальный агент. Не масштабируется.
- **Вариант C** (Argus → x402 → adapter → native Secretariat) — лишний слой.
- **Argus как полноценный x402 SDK** — overkill для test lab.
- **Параллельный порядок** (Secretariat edge и Argus client одновременно) —
  отвергнут: wire-формат не известен статически, угадывать двумя сторонами
  = interop-фейл без возможности установить виновника.
